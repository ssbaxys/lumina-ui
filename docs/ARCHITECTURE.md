# Lumina UI: архитектура

## Главная идея

Весь интерфейс (дерево виджетов, раскладка, стили, анимации, события) живёт в модуле `core`
на чистой Java 17 без единого класса Minecraft. Модули загрузчиков тонкие: они реализуют
только рисование примитивов, пересылку ввода и точку входа мода.

```
core/                    чистая Java 17, юнит-тесты без запуска игры
forge-1.20.1/            Forge 47, Java 17  (ModDevGradle legacyforge)
  src/main/              библиотека luminaui
  src/testmod/           тестовый мод luminatest (точки входа)
neoforge-1.21.1/         NeoForge 21.1, Java 21 (ModDevGradle)
  src/main/, src/testmod/
testmod-common/          витрина: страницы тестового мода на API ядра + прогон без игры
```

Исходники `core` компилируются прямо в jar каждого загрузчика, поэтому на выходе один мод
без вложенных библиотек. Добавить новую версию игры = скопировать модуль загрузчика
(~7 небольших файлов) и поправить API рендера.

## Слои ядра (`io.github.ssbaxys.lumina`)

| Пакет | Что делает |
|---|---|
| `render` | `Canvas` (интерфейс рисования для виджетов), `AbstractCanvas` (стек трансформаций, клип, прозрачность, отсечение невидимого), `Brush` (сплошная и градиенты), `ColorStops`, `ColorSpace`, `Gradients`, `BlendMode`, `Radii`, `Shadow`, `Outline`, `Color` |
| `layout` | Двухпроходная раскладка measure/arrange: `FlexLayout` (flexbox: gap, grow/shrink, justify, align), `StackLayout` (слои), абсолютное позиционирование, `Dim` (auto / px / % / fill) |
| `node` | `UiElement` (узел дерева), `UiRoot` (корень: hover, нажатия, фокус, Tab-навигация, диспетчер событий, кадр) |
| `style` | `StyleKey` (типизированные свойства с плотными id), `Style` (значения + варианты для hover/pressed/focused/disabled/checked), `ComputedStyle` (текущие значения, переходы по свойствам, слой анимаций), `Theme` (стили классов и токены `ThemeVar`/`Tokens`), `Transition` |
| `anim` | `Animator` (держит только активные анимации), `AnimatedFloat` (твин или пружина), `Easing` (23 кривые, cubic-bezier, steps, spring), `Interpolator`, `Motion` (таймлайн: sequence/parallel/delay/call), `Keyframes`, `Tween`, `Playback` (циклы, yoyo, скорость) |
| `event` | Типизированные события с фазами захвата и всплытия: мышь, колесо, клавиатура, символы, фокус |
| `reactive` | `Signal`, `Computed` (автоматическое отслеживание зависимостей) для привязки данных к виджетам |
| `widget` | `Widget<S>` (типобезопасный fluent-API), `Panel`, `Label`, `Button`, `ScrollPanel`, `Toggle`, `Slider`, `ProgressBar`, `RingProgress`, `ColorPicker` |
| `fx` | `FxLayer` (слой эффектов), `Particles` (частицы в плоских массивах), `SpriteSheet`, `VanillaFx` (огонь, взрыв, TNT, лава, дым, тряска на ванильных текстурах) |
| `markdown` | `MarkdownParser` → дерево `Md` → `MarkdownLayout` (плоские операции рисования) → виджет `Markdown` |
| `platform` | `Platform`: всё, что ядру нужно от игры (метрики шрифта, буфер обмена, звук, время) |

## Как это решает требования

**Без рефлексии.** Платформа передаётся явно (`Lumina.init(platform)`), без ServiceLoader.
Свойства стилей и типы событий получают целочисленные id при регистрации, поэтому значения
и слушатели лежат в массивах по индексу. Расширение (свои свойства, события, раскладки,
виджеты) делается обычным кодом: `StyleKey.builder(...).register()`, `EventType.create(...)`,
`implements Layout`, `extends Widget<MyWidget>`.

**Производительность.**
- Раскладка кэшируется и пересчитывается только после `invalidateLayout()` и только по цепочке предков.
- Стиль для каждой комбинации состояний считается один раз и кэшируется в `Style`; смена hover стоит O(1).
- Наследуемые свойства (цвет текста) не копируются по дереву, а читаются у родителя лениво.
- `AbstractCanvas` хранит состояние в плоском float-массиве, отбрасывает невидимые примитивы и
  меняет scissor только при реальном изменении клипа. Кадр рисуется почти без аллокаций.
- Простые прямоугольники собираются в один буфер и рисуются одним вызовом.
- Аниматор пуст в покое: никакой работы, если ничего не движется.
- Поддерево, целиком невидимое (за краем экрана или области прокрутки), не обходится вовсе.
  Элементам, которые рисуют за своими границами, ставится `setOverflowsBounds(true)`.

**Красота.** Скругления (разные радиусы углов), обводки и мягкие тени рисуются SDF-шейдером
(`assets/luminaui/shaders/core/rounded_rect.*`) со сглаживанием ровно в один физический пиксель
при любом GUI scale. Градиенты, прозрачность и масштаб наследуются по дереву. Переходы между
состояниями (hover, нажатие, фокус) анимируются из стиля темы.

**Гибкость.** Тема задаёт стили по классу виджета (можно несколько классов), inline-стиль накладывается поверх. Стили ссылаются на токены темы — смена одного токена плавно перекрашивает весь интерфейс. Подробно: [STYLING.md](STYLING.md). Экраны можно описывать HTML и CSS с привязкой логики: [MARKUP.md](MARKUP.md). Любую
раскладку и любой виджет можно заменить своим. Сигналы связывают данные с интерфейсом.

## Пример

```java
Signal<Integer> clicks = Signal.of(0);

Panel window = Panel.column().gap(10).width(Dim.px(260)).add(
        new Label("Lumina UI").scale(1.5f),
        Label.bound(clicks.map(c -> "Нажатий: " + c)),
        new Button("Нажми", () -> clicks.update(c -> c + 1))
                .style(s -> s.set(Styles.RADIUS, Radii.all(12))));

Minecraft.getInstance().setScreen(new LuminaScreen(Component.literal("Пример"),
        screen -> new UiRoot(window)));
```

Полная витрина возможностей — тестовый мод `luminatest` (см. README): клавиша K, `/luminatest`
или кнопка «Lumina» в меню. Маленькое демо самой библиотеки: `/lumina demo`.

## Дальнейшие шаги

- Батчинг SDF-фигур: свой формат вершин с радиусами в атрибутах, чтобы рисовать все фигуры одним вызовом.
- Виджеты: поле ввода, выпадающий список, тултипы, модальные окна, сетка.
- Nine-slice текстуры.
- Загрузка тем из JSON (ресурс-паки), горячая перезагрузка.
- Встраивание в чужие экраны (оверлей поверх `AbstractContainerScreen`) и HUD.
